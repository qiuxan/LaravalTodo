# Sanctum User-Owned Todos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Laravel Sanctum API token authentication and make each authenticated user manage only their own todos.

**Architecture:** Use Sanctum personal access tokens for API auth. Auth endpoints issue and revoke bearer tokens. Todo endpoints move behind `auth:sanctum`, create todos through the authenticated user's relationship, and scope read/update/delete operations to the authenticated user.

**Tech Stack:** Laravel 13, Laravel Sanctum, MariaDB, Eloquent relationships, FormRequest validation, Feature tests with `actingAs()` and bearer-token style auth coverage.

## Global Constraints

- Use Sanctum API token auth, not SPA cookie/session auth.
- Do not add CSRF handling for bearer-token API requests.
- Keep the existing Todo action pattern where it still helps.
- Do not add a Repository layer.
- Existing imported DummyJSON todos may keep `user_id = null` for this phase.
- Authenticated users must not see, update, or delete another user's todos.
- Prefer `404` for another user's todo access to avoid revealing resource existence.
- Tests must use `laravel_todo_test`, not the development database.

                'token' => $token,

}

public function login(LoginRequest $request): JsonResponse
{
    $user = User::where('email', $request->validated('email'))->first();

    if (! $user || ! Hash::check($request->validated('password'), $user->password)) {
        throw ValidationException::withMessages([
            'email' => ['The provided credentials are incorrect.'],
        ]);
    }

    $token = $user->createToken('api-token')->plainTextToken;

    return response()->json([
        'data' => [
            'user' => [
                'id' => $user->id,
                'name' => $user->name,
                'email' => $user->email,
            ],
            'token' => $token,
        ],
    ]);
}

## Self-Review Notes

- The plan uses Sanctum token auth and deliberately avoids SPA cookie CSRF flow.
- Todo ownership is learned through relationships, authenticated route middleware, scoped queries, and cross-user access tests.
- DummyJSON import remains global for this phase to avoid mixing queue user context into the first auth exercise.
- Tests are split by concern: `AuthTest` for auth, `TodoApiTest` for ownership, existing import tests for queue/import behavior.
- The plan returns `404` for cross-user todo access to avoid resource existence disclosure.
